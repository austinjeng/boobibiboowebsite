## Project Overview

**Explore Bingo Map** (快樂探索 Bingo × 情境避雷地圖) - A location-based exploration game that uses Bingo tasks to guide city exploration, recording experiences with "happiness tags" and an optional "caution notes" system.

Core philosophy: Happiness-first UX. The map showcases positive experiences; caution info is optional and presented gently.

## Commands

```bash
npm run dev      # Start development server (http://localhost:3000)
npm run build    # Production build
npm run start    # Start production server
npm run lint     # Run ESLint

# BetterAuth CLI (after schema changes)
npx @better-auth/cli@latest generate   # Generate auth schema

```

## Tech Stack

- **Framework**: Next.js 16.x (App Router)
- **Language**: TypeScript (strict mode)
- **UI**: React 19.x, shadcn/ui components
- **Styling**: Tailwind CSS v4
- **Database**: Supabase PostgreSQL (via `pg` driver)
- **Auth**: BetterAuth with Google OAuth only
- **Auth UI**: @daveyplate/better-auth-ui (pre-built shadcn components)
- **Fonts**: Geist Sans/Mono via next/font

## Environment Variables

Required in `.env.local`:

```env
DATABASE_URL              # Supabase PostgreSQL connection (use pooler port 6543)
BETTER_AUTH_SECRET        # 32+ char random string for session signing
BETTER_AUTH_URL           # http://localhost:3000 (dev) or production URL
GOOGLE_CLIENT_ID          # From Google Cloud Console
GOOGLE_CLIENT_SECRET      # From Google Cloud Console
```

Google OAuth redirect URI: `{BETTER_AUTH_URL}/api/auth/callback/google`

## Auth Architecture

- **BetterAuth** handles authentication with Google OAuth only (no email/password)
- Auth tables (`user`, `session`, `account`, `verification`) are auto-generated by BetterAuth CLI
- BetterAuth's `user` table replaces PRD User model (`image` field serves as `avatarUrl`)
- Route protection via `src/proxy.ts` (Next.js 16 uses `proxy.ts` not `middleware.ts`)
- Server-side session: `auth.api.getSession({ headers: await headers() })`
- Client-side session: `authClient.useSession()`

## Database Schema

**BetterAuth tables** (auto-generated): `user`, `session`, `account`, `verification`

**App tables** (in `src/db/schema.sql`):

- `place` - Locations with lat/lng
- `check_in` - User check-ins with happiness tags, cautions, contexts
- `bingo_card` - Weekly task card themes
- `bingo_task` - 25 tasks per card (index 0-24)
- `bingo_completion` - Links user task completions to check-ins
- `room` - Multiplayer rooms with unique codes
- `room_member` - Room membership
